Week 6: Feature Engineering

Transformations, nonlinear terms, categories, interactions, place fixed effects, and 10-fold cross-validation for rent prediction.
Published

October 9, 2026

What We Did

This week, we engineered features for linear regression using 2023 ACS five-year data for Philadelphia census tracts. We compared log transformations, squared terms, categorical variables, interactions, and planning-district fixed effects. For each candidate model, we focused on prediction in dollars using the same 10-fold cross-validation (CV) split and its root mean squared error (RMSE).

Key Concepts

  • A linear model is linear in the features supplied to it. Transforming those features allows nonlinear relationships, group differences, and spatial heterogeneity.
  • A coefficient’s interpretation depends on whether the outcome or predictor is logged, squared, or interacted with a category.
  • Evaluate a model of log(rent) by back-transforming predictions to dollars before calculating RMSE against rent.
  • Categorical variables use a reference group; changing that group changes coefficient comparisons, not fitted predictions.
  • Fixed effects capture shared group-level differences, but they do not identify their causes and cannot directly predict a category absent from training.
  • For prediction, compare candidate models with out-of-sample CV RMSE. A low p-value or strong training fit is not enough, and an association is not necessarily causal.

Note

1. What Is Feature Engineering?

A linear regression can draw only a straight-line relationship through the features it receives. Feature engineering means deciding what information and transformations to supply. A model can remain linear in its coefficients while using log(income), I(bldg_age^2), distance bands, interactions, or district indicators to represent relationships that are not simply straight lines in the original variables.

For prediction, the practical question is whether the new features lower error on unseen observations. For interpretation, the practical question is what a one-unit change in each transformed feature means. Neither a predictive improvement nor a regression coefficient by itself establishes causation.

2. Data, Baseline Model, and Fixed CV Folds

The class example uses approximately 377 Philadelphia census tracts from the 2023 ACS five-year data. The tract geometries are projected to EPSG:2272, whose units are feet. The variables are:

Variable Meaning
rent Median gross rent, in dollars
income Median household income
pct_renter Percentage of renter-occupied households
bldg_age Building age, calculated as 2023 - yr_builtE
dist_ch_mi Distance from the tract to City Hall, in miles

The baseline specification and result log are:

f0 <- rent ~ income + pct_renter + bldg_age + dist_ch_mi
m0 <- lm(f0, data = tracts)
model_log <- tibble(
  model = "m0",
  added = "baseline",
  cv_rmse = cv_rmse(f0, tracts)
)
model_log

f0 is a formula, not a fitted model; lm() fits it. summary(m0) reports estimated coefficients. Here, model_log is a table of model results—“log” does not mean logarithm. Baseline 10-fold CV RMSE was approximately $265; lower is better.

The comparison uses one reproducible set of ten folds. In each round, nine folds train the model and the remaining fold supplies unseen validation observations:

set.seed(5080)
folds <- sample(rep(1:10, length.out = nrow(tracts)))

cv_rmse <- function(f, data, log_outcome = FALSE) {
  preds <- numeric(nrow(data))
  for (k in 1:10) {
    m <- lm(f, data = data[folds != k, ])
    p <- predict(m, newdata = data[folds == k, ])
    if (log_outcome) p <- exp(p) # Return predictions to dollars.
    preds[folds == k] <- p
  }
  sqrt(mean((data$rent - preds)^2))
}

Every candidate model must use the same folds for a fair comparison. This helper assumes data has the same row count and order as the data used to create folds; rebuild the folds if those rows change. The examples in this note depend on the class tracts object and are not run when this note is rendered.

3. Log Transformations

Why log a predictor?

Income is often right-skewed. log(income) compresses high values and makes equal proportional changes approximately equally spaced. A $20,000 change from $20,000 to $40,000 is economically different from a $20,000 change from $180,000 to $200,000, even though their absolute differences match.

ggplot(tracts, aes(income)) + geom_histogram(bins = 40)
ggplot(tracts, aes(log(income))) + geom_histogram(bins = 40)

Four common model forms

Model form Formula example Coefficient interpretation
Level–level y ~ x A one-unit increase in X corresponds to a \(\beta\)-unit change in Y.
Level–log y ~ log(x) A 1% increase in X corresponds to approximately a \(\beta/100\)-unit change in Y.
Log–level log(y) ~ x A one-unit increase in X corresponds to approximately a \(100\beta\)% change in Y.
Log–log log(y) ~ log(x) A 1% increase in X corresponds to approximately a \(\beta\)% change in Y; \(\beta\) is an elasticity.

For rent ~ log(income) + ..., suppose the estimated income coefficient is 502.1787. A 1% income increase is associated with about $5.02 higher predicted monthly rent. For a 10% increase, use the exact log change:

\[ 502.1787\log(1.10)\approx\$47.86. \]

For log(rent) ~ log(income) + ..., a coefficient of 0.36334 means that a 1% income increase is associated with approximately a 0.363% rent increase. In a log–level model, the exact percentage change for a one-unit increase in X is \(100(e^\beta-1)\)%, rather than exactly \(100\beta\)%.

Zeros and negative values

log(0) is -Inf. For nonnegative counts such as crimes, trees, or 311 calls, log1p(x) computes \(\log(1+x)\) and retains zero observations:

log(0)
log1p(c(0, 1, 10, 100))

For small counts, the ordinary percentage-change interpretation of log(x) does not transfer exactly to log1p(x). Negative values require a transformation chosen for the substantive data context.

A logged outcome must be evaluated in dollars

A training residual RMSE of about 0.1885 for log(rent) is on a log scale. It cannot be compared directly with a training residual RMSE of about $259.55 for an unlogged rent model. To compare predictive accuracy, return each logged prediction to dollars, then compute CV RMSE against observed rent:

f_logy <- log(rent) ~ log(income) + pct_renter +
  bldg_age + dist_ch_mi
cv_rmse(f_logy, tracts, log_outcome = TRUE)

Because \(\exp(E[\log Y])\neq E[Y]\), simply exponentiating a fitted log outcome does not automatically give an unbiased prediction of mean rent; the note’s back-transformation is for comparison on the original dollar scale.

4. Squared Terms and Curvature

If a flexible smooth on a scatterplot bends while a straight geom_smooth(method = "lm") line misses that pattern, a quadratic term may help:

f_sq <- rent ~ log(income) + pct_renter + bldg_age +
  I(bldg_age^2) + dist_ch_mi
m_sq <- lm(f_sq, data = tracts)

In an R formula, I(bldg_age^2) means the literal square; ^ otherwise has special formula syntax. For \(Y=\beta_0+\beta_1x+\beta_2x^2\), the marginal slope at a particular \(x\) is \(\beta_1+2\beta_2x\). Do not interpret \(\beta_1\) or \(\beta_2\) in isolation as a constant effect. A positive linear term with a negative square makes an inverted U; a negative linear term with a positive square makes a U.

The turning point is \(x^*=-\beta_1/(2\beta_2)\). In the class example, the building-age coefficients were about \(-28.00445\) and \(+0.1823244\), giving a minimum around 76.8 years. That is near the upper end of the observed age range of roughly 5–85 years. The pre-1940 Census category is encoded as “1939 or earlier,” which bunches old buildings together; this fitted curve is not a natural law. Predictions far outside the observed age range can be implausible.

5. Categorical Variables and Reference Groups

Use categorical features for naturally distinct groups, such as zoning, planning district, or housing type. A numeric variable can also be grouped if the relationship seems to change in steps rather than smoothly. For example:

tracts <- tracts %>% mutate(
  renter_band = cut(
    pct_renter,
    breaks = c(0, 33, 66, 100),
    labels = c("Mostly owners", "Mixed", "Mostly renters"),
    include.lowest = TRUE
  )
)
tracts %>% st_drop_geometry() %>% count(renter_band)

The three example bands contain 88, 210, and 79 tracts. cut() uses numeric break points, case_when() supports custom rules, and factor() tells R to treat values as categories. With an intercept and \(k\) categories, the model normally uses \(k-1\) dummy variables, generated by model.matrix().

If Core is the reference in a distance-ring model, coefficients ringInner = -122.2774 and ringOuter = -164.1935 mean that, holding other features fixed, predicted rent is about $122.28 lower in Inner and $164.19 lower in Outer than in Core. They do not mean that rent in Outer is negative. Changing the reference group changes coefficient comparisons, not the fitted predictions:

tracts_r <- tracts %>% mutate(ring = relevel(ring, ref = "Outer"))

Binning sacrifices information: replacing continuous dist_ch_mi with Core/Inner/Outer treats distinct distances within the same band alike. If the true relationship is smooth, this can worsen prediction.

6. Interactions: Different Slopes by Group

An interaction is useful when the relationship between X and Y differs by group:

f_int <- rent ~ log(income) * ring + pct_renter +
  bldg_age + I(bldg_age^2)
m_int <- lm(f_int, data = tracts)

In R formula syntax, a * b expands to a + b + a:b, whereas a:b adds only the interaction. With Core as the reference, the log(income) slope is 653.6974. The Inner interaction changes it by −219.1028, giving about 434.59; the Outer interaction changes it by −244.4214, giving about 409.28. Because the outcome is rent in dollars and income is logged, a 1% income increase corresponds to approximately the group-specific slope divided by 100 dollars of monthly rent.

Interacting every feature with every group increases the number of parameters quickly. With only about 377 tracts, that can overfit.

7. Place Fixed Effects

7.1 District intercepts

A place fixed effect gives each district its own intercept through a categorical district variable. It can absorb shared, unmeasured background differences—such as reputation, schools, transit, and history—but cannot reveal which of those mechanisms matters. The class example assigns each tract to the Philadelphia planning district with which it has the greatest area overlap, across 18 planning districts:

tracts <- tracts %>%
  st_join(
    districts %>% select(district = dist_name),
    largest = TRUE
  ) %>%
  mutate(district = factor(district))

f_fe <- rent ~ log(income) + pct_renter + bldg_age +
  I(bldg_age^2) + district
m_fe <- lm(f_fe, data = tracts)

In this example, the log(income) coefficient fell from about 519.74 before district effects to 427.39 after them. The earlier estimate mixed between-district and within-district differences; with district intercepts, the coefficient primarily compares tracts within districts. This change does not automatically establish a causal effect.

7.2 The unseen-category problem in CV

A fixed-effect model cannot directly predict a district level that did not appear in its training fold. count(district) revealed that Lower South had only one tract; a 10-fold CV round could place that one tract entirely in validation, causing predict() to fail. The class solution merged districts with fewer than ten tracts into a nearby district for a CV-ready variable:

small <- tracts %>% st_drop_geometry() %>%
  count(district) %>% filter(n < 10 | is.na(district)) %>%
  pull(district)

is_small <- tracts$district %in% small | is.na(tracts$district)
nearest <- st_nearest_feature(tracts[is_small, ], tracts[!is_small, ])

tracts <- tracts %>%
  mutate(district_cv = as.character(district))
tracts$district_cv[is_small] <-
  as.character(tracts$district[!is_small][nearest])
tracts <- tracts %>%
  mutate(district_cv = factor(district_cv))

At least about 10 observations per group is a useful 10-fold CV rule of thumb; more is safer. Other approaches include combining rare levels into “Other” (for example, with fct_lump_min()), although that may not make geographic sense, or using coarser spatial units. District IDs such as 1–18 are labels, not a continuous numeric predictor, so they must be represented as a factor.

7.3 Fixed effects versus measured spatial features

  • District fixed effects answer which districts differ in baseline rent, capturing leftover shared district variation. They do not explain the mechanism or generalize directly to a new district.
  • Spatial features such as distance to transit or parks and nearby crime describe measurable attributes. They can reveal associations with those attributes and may generalize conditionally to new locations.

Both can be used together: measured spatial features may explain some differences, while district effects absorb remaining shared district variation. The class note points ahead to nearby-neighbor (kNN) features on October 16.

8. Model Comparison: 10-Fold CV RMSE

All values below are approximate class results in dollars, using the same ten folds. Lower CV RMSE means better out-of-sample rent prediction in this comparison.

Model Feature change 10-fold CV RMSE
m0 Baseline $265
m1 log(income) $265
m2 log(rent) + log(income); predictions back-transformed $263
m3 bldg_age^2 in a level-rent model $261
m4 ring replaces dist_ch_mi $265
m5 log(income) × ring $264
m6 District fixed effects, with rare districts merged with nearby districts $256

The m2 model and the later m3–m6 models are separate candidate specifications, not a single formula built cumulatively at every step. m6 has the lowest CV RMSE in this example, but that does not imply that fixed effects are always the best choice.
